# Map, Set, WeakMap, WeakSet

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- `Map`: ключи любые (объекты тоже), `size`, порядок вставки, быстрые add/get/delete; в отличие от объекта — нет приведения ключей к строке и нет прототипа.
- `Set`: уникальные значения, `has/add/delete`, порядок; дедупликация `[…new Set(arr)]`.
- `WeakMap/WeakSet`: только объектные ключи, нельзя итерировать и узнать размер.
- Смысл «weak»: ключи держатся слабо — не мешают сборщику мусора удалить объект. Кеш метаданных объекта, приватные данные, хуки фреймворков.

## Что могут спросить дополнительно
- Map vs Object: когда что? (динамические ключи/частые удаления/не-строки → Map)
- Почему WeakMap нельзя перебрать? (сборщик может удалить в любой момент — нечестно итерировать)

## Красные флажки
- «WeakMap для экономии памяти в цикле» без понимания GC.
