# HTTP-методы и коды ответов

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- Методы: GET (чтение, идемпотентный, кэшируемый), POST (создание, не идемпотентный), PUT (полная замена, идемпотентный), PATCH (частичное изменение), DELETE, OPTIONS (preflight CORS), HEAD.
- Идемпотентность: повтор запроса даёт тот же результат (важно при ретраях).
- Безопасность метода = не меняет состояние сервера (GET/HEAD/OPTIONS).
- Коды: 200 ок; 201 создано; 204 без тела (DELETE); 301 постоянный редирект / 302 временный; 304 Not Modified (кэш); 400 плохой запрос; 401 не аутентифицирован / 403 нет прав; 404; 409 конфликт; 422 ошибка валидации; 429 слишком много запросов (rate limit); 500 сервер; 502/504 шлюз/таймаут.

## Что могут спросить дополнительно
- 401 vs 403 (кто ты vs что тебе можно).
- Почему PUT идемпотентен, а POST нет (повторный POST создаст дубль).
- Где смотреть 429 и что делать (Retry-After, backoff).

## Красные флажки
- Путаешь 401 и 403.
