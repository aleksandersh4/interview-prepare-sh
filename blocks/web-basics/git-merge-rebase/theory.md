# Git: merge vs rebase, reset vs revert, ветвление

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- `merge` — сливает ветки, создаёт merge-commit, история честная (граф).
- `rebase` — переносит коммиты на новую базу, история линейная; не ребейсь в общие ветки (переписывание истории).
- `reset`: `--soft` (двигает HEAD, изменения в index), `--mixed` (default, в working dir), `--hard` (стирает изменения).
- `revert` — новый коммит, отменяющий старый; безопасен для общих веток.
- Стратегии: GitFlow (develop/release/hotfix — тяжёлый), Trunk-Based (все в main короткими ветками + фичефлаги) — мейнстрим современных команд.

## Что могут спросить дополнительно
- Cherry-pick, stash, `git reflog` (спасение после «потерянных» коммитов).
- Как разрешаешь конфликты? (понимание обеих сторон, мелкие PR).

## Красные флажки
- `reset --hard` в общую ветку; rebase в main.
