# Холодные и горячие потоки, share/shareReplay

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- Cold: каждый подписчик — своё выполнение (HTTP-запрос повторится на каждую подписку).
- Hot: один источник, подписчики слушают «эфир» (fromEvent, Subject); опоздавшие не видят прошлое.
- Превращение cold → hot: `share()`; `shareReplay(n)` — новым подписчикам повторяет последние n значений.
- `refCount: true` (дефолт share): когда подписчиков 0 — источник отписывается; `{resetOnRefCountZero}` — нюансы.

## Что могут спросить дополнительно
- Почему без share() HTTP уходит дважды при двух async-пайпах?
- shareReplay(1) для конфига — типовой кейс.

## Красные флажки
- «shareReplay всегда и везде» без понимания refCount.
