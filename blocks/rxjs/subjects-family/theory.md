# Subject, BehaviorSubject, ReplaySubject, AsyncSubject

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- `Subject` — одновременно источник событий и наблюдатель: у него есть `next()/error()/complete()`, и на него же подписываются. Подписчики получают только события, случившиеся ПОСЛЕ подписки.
- `BehaviorSubject(initial)` — хранит последнее; новый подписчик сразу получает его; `getValue()`; идеально для «текущее состояние + изменения».
- `ReplaySubject(n)` — повторяет последние n значений новому подписчику.
- `AsyncSubject` — отдаёт последнее значение только по завершении (редко).
- На КАЖДУЮ подписку нужна отписка (`takeUntilDestroyed` или `async` pipe), иначе утечка.

## Что могут спросить дополнительно
- Какой subject для поиска «текущий пользователь»? (Behavior)
- Subject vs signal для стора — когда что (signal для состояния, subject для событий).

## Красные флажки
- BehaviorSubject без initial или «Subject хранит значение».
