# 09 · Promise и async/await

> Задачи — карточками на странице темы; файлы: `01-task.js`, `02-task.js`… в этой папке.

## Теория (кратко)

- **Промис** — объект-placeholder результата: состояния `pending → fulfilled | rejected`,
  settle происходит один раз и навсегда (после `fulfilled` в `rejected` перейти нельзя).
- `then(onFulfilled, onRejected)` возвращает **новый** промис → цепочки; значение, возвращенное
  колбэком, уезжает дальше; если колбэк вернул промис — цепочка ждёт его.
- Ошибки «проваливаются» (skip) через `then` до ближайшего `catch`. После `catch` цепочка
  снова «здорова» (fulfilled), если catch не бросил.
- `finally(fn)` — выполняется при любом исходе, **не меняет** значение/ошибку, для очистки.
- `async` функция всегда возвращает промис; `throw` внутри неё = reject.
  `await` разворачивает промис; ошибки ловятся обычным `try/catch`.
- **`await` в цикле — последовательно** (каждая итерация ждёт прошлую).
  `Promise.all(arr.map(asyncFn))` — параллельно. Это спрашивают почти всегда.
- Комбинаторы:
  - `Promise.all` — все fulfill → массив результатов; первый reject → reject всего (fail-fast);
  - `Promise.allSettled` — всегда fulfill, массив `{status, value|reason}`;
  - `Promise.race` — первый settle (неважно чем);
  - `Promise.any` — первый fulfill; все reject → `AggregateError`.
- Промисификация: обернуть колбэк-API в `new Promise((resolve, reject) => ...)`.
- Отменить промис нельзя; отменяют операцию (`AbortController` для fetch).
- Необработанный reject → событие `unhandledrejection` (в браузере видно в консоли).

## Примеры

```js
// Последовательно: ~300 мс
for (const id of ids) { await load(id); }

// Параллельно: ~100 мс
await Promise.all(ids.map((id) => load(id)));

// Цепочка с ошибкой
getUser(id)
  .then((u) => u.orders)
  .catch((e) => [])          // дальше снова fulfilled
  .then((orders) => render(orders))
  .finally(() => hideLoader());

// Промисификация колбэка
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
```

## Задачи (карточки на странице)

_Тесты асинхронные: результаты допишутся в вывод с задержкой — это нормально._

1. **`sleep(ms)`** — промис, resolve через `ms`.
2. **`promiseAll(promises)`** — свой `Promise.all`: массив результатов в исходном порядке,
   reject сразу при первом отказе (не забудь: обычные значения тоже валидны).
3. **`retry(fn, attempts, delayMs)`** — повторять до успеха или конца попыток, пауза между попытками.
4. **`mapWithLimit(items, fn, limit)`** — как map, но не больше `limit` одновременных `fn`.
5. Демо: последовательный vs параллельный `await` с замером времени.
