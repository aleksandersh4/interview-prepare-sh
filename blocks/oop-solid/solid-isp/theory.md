# ISP: разделение интерфейсов

> Теоретическая тема. Попроси ассистента: «проверь меня: <тема>» — он устроит устный опрос по вопросам ниже.

## Как отвечать (скелет)
- Клиент не должен зависеть от методов, которые не использует: «толстый» интерфейс дробим на роли.
- Пример: `Animal { fly; swim; run }` → `Flyable`, `Swimmable` — пингвину не нужен fly.
- В TS/Angular: маленькие интерфейсы сервисов, `Pick`-типы для потребностей компонента.
- Выгода: понятные зависимости, простые стабы в тестах.

## Что могут спросить дополнительно
- Связь ISP с SRP (роли = ответственности).

## Красные флажки
- Один God-interface на весь домен.
