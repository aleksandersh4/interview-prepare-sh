# CONTEXT — контекст разработки и требований

_Обновлено: 2026-11-17. Этот файл — «выжимка памяти» проекта: зачем он, как устроен,
какие требования соблюдает. Читай его перед любыми изменениями стенда._

## 1. Назначение

Учебный стенд для подготовки к JS-собеседованиям: 10 тем, в каждой — краткая теория,
популярные вопросы с интервью и задачи с автопроверкой. Пользователь пишет решения
в браузере (песочница) или в WebStorm, получает мгновенный зелёный/красный фидбек,
а ассистент делает ревью решений по файлам (цикл: «проверь 02» → разбор).

Заказчик и единственный пользователь готовит собеседования Angular-разработчика
(см. его план подготовки в WebstormProjects), поэтому JS-ядро — фундaмент, стенд
должен покрывать канон интервью: debounce/throttle, полифиллы, deep clone, event loop.

## 2. Жёсткие требования

1. **Оффлайн и без сборки для пользователя.** Никаких CDN в рантайме. Единственные
   сторонние файлы — `vendor/marked.min.js` и `vendor/codemirror.bundle.js` (лежат в репо).
2. **Два режима работы:**
   - `http://` (`node serve.js` → 127.0.0.1:8127) — полный: теория-панель, редактор
     с подсветкой, запуск по карточкам, автосейв, запись в файлы;
   - `file://` — дегрейд: без fetch, карточки подгружаются `<script>`-цепочкой,
     решения правятся в WebStorm, F5 = перезапуск.
3. **Файл — источник истины, localStorage — только черновик** (автосейв, дебаунс 400 мс).
   При расхождении — явный выбор (баннер/кнопка «открыть черновик»), автозатирание
   черновика программной загрузкой запрещено (флаг `applying` в editor.js — был баг).
4. **Запись в файлы** — File System Access API (Chrome/Edge). Кнопка «📁 Папка темы»
   биндит directory handle на сессию; пер-карточное «💾» пишет task-файл без диалогов.
   Персист хендла в IndexedDB — в планах, не сделан.
5. **Задачи самодостаточны**: каждый task-файл исполняется независимо от соседей
   (свои константы, свои хелперы). Если задаче нужен `sleep`/sandbox из другой задачи —
   в файл кладётся готовая копия-хелпер. Это требование миграции 2026-11-17.
6. **Синхронизация WebStorm ↔ браузер**: обе стороны читают/пишут одни файлы;
   статусы («синхронизирован ✓» / «есть несохранённые изменения») — на каждой карточке.
7. **Читаемость «где писать»**: код пользователя — между маркерами
   `// ▼▼▼ ПИШИ СВОЙ КОД ЗДЕСЬ ▼▼▼` … `// ▲▲▲ КОНЕЦ КОДА ▲▲▲`; проверки ниже маркера.
   Маркеры расставляет `build/annotate-stubs.mjs` (идемпотентно, по `// TODO` внутри
   функции + балансу фигурных скобок).
8. Репозиторий публичный на GitHub (`aleksandersh4/interview-prepare-sh`), ветка `main`,
   пушит ассистент по команде «запушь» (креды в Git Credential Manager).

## 3. Структура

```
index.html / style.css   — страница: меню тем, теория, тулбар темы, карточки задач, sandbox
runner.js                — хелперы check/log/section/tryRun (фабрика на карточку),
                           меню TOPICS, file://-цепочка, домашняя страница
editor.js                — движок карточек: fetch index.json, CodeMirror per card,
                           run per card / run all, автосейв, баннер черновика,
                           dir handle + сохранение, Ctrl+Enter/Ctrl+S
serve.js                 — статический сервер (порт 8127), не нужен на file://
vendor/                  — marked.min.js, codemirror.bundle.js (собран, не редактируется руками)
build/                   — сборка CodeMirror (npm run build), annotate-stubs.mjs,
                           migrate-to-folders.mjs (одноразовая миграция структуры)
topics/<NN-slug>/
    theory.md            — теория + вопросы с собеседований (рендерится на странице)
    index.json           — порядок карточек: [{file, title, kind: task|demo}]
    01-task.js …         — задача: код с маркерами + проверки; имя = порядок + вид
    0M-demo.js           — демо/квиз (без маркеров, только показать/объяснить)
```

## 4. Контракты

- `check(название, факт, ожидание)` — deep-equal, NaN===NaN; вывод «получено/ожидалось».
- `tryRun(() => …)` — безопасный вызов для тестов, чтобы нерешённая задача не роняла файл.
- Запуск кода карточки — `new Function('section','log','check','tryRun', code)`:
  хелперы привязаны к output-у карточки, значит async-проверки (setTimeout/then)
  допишут результат в свою карточку, а не в «текущую».
- `section()` внутри task-файла оставлен — даёт заголовок в выводе карточки.
- Тесты с таймерами дописывают результаты позже — это норма, не баг.
- Карточка «Запустить» чистит свой output и общий `#sandbox` (DOM-тема).

## 5. Сборка и скрипты

- CodeMirror: `cd build && npm install && npm run build` → `vendor/codemirror.bundle.js`
  (IIFE, `window.CMEditor = { EditorView, extensions }`). npm может потребовать
  `npm install-scripts approve esbuild`.
- `node build/annotate-stubs.mjs` — (пере)расстановка маркеров после правки задач.
- `node build/migrate-to-folders.mjs` — одноразовая миграция «монолит → папки»,
  оставлен для истории; повторный запуск ничего не делает (источник уже перенесён).

## 6. Цикл работы с ассистентом

- Пользователь решает задачи (карточка зеленеет) → «проверь 02-scope-and-closures» →
  ассистент читает `topics/02-*/NN-task.js`, ревью: решение, краевые случаи,
  вопросы «на добивание» (объяснять просто, без жаргона).
- «запушь изменения» → коммит (сообщения: английский, коротко суть) → push.
- Крупные фичи сначала обсуждаются («давай обсудим»), мелкие правки — сразу.
